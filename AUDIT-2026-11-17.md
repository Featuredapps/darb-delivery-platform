# DARB pre-release audit — 2026-11-17 (updated)

## Scope and release decisions
- Release scope: customer, vendor, driver, and admin roles.
- Cash on delivery is the only payment path treated as launch-ready. Online payment remains disabled until a provider is selected, integrated, tested, and explicitly approved.
- Launch sequence: closed testing before public release.
- No paid service, SMS send, prepaid top-up, or infrastructure upgrade without explicit owner approval.

## Current implementation status

### Fixed or present in source
- Admin mobile route and queues for pending vendor and driver applications were added.
- Mobile API client restores access tokens, attempts refresh-token rotation after missing/expired access tokens, retries once, and clears tokens after rejected refresh.
- Android manifest cleartext traffic is disabled in the current CI-built app.
- Initial Prisma migration is committed under `backend/prisma/migrations/20261116162000_initial/`; repository documentation states it was applied to a disposable PostgreSQL/PostGIS database in CI.
- MsgPlus adapter now targets `POST /api/send` and sends `sender_id`, `template_id=3`, `numbers`, and `vars` with `P1=مستخدمنا`, `P2=درب`, `P3=<six-digit OTP>`. Render Blueprint now expects `MSGPLUS_SENDER_ID`.

### Still unverified or incomplete
- MsgPlus OTP delivery has not been tested live. Sender/template approval and successful receipt on a real Syrian number remain to be confirmed. Do not consume the owner's reserved free SMS messages without approval.
- No device acceptance test has confirmed login, token refresh, ordering, vendor acceptance, driver claim, or delivery end to end.
- Automated backend tests now cover phone normalization and selected order-lifecycle cases (11 tests total). OTP lifecycle, payment flows, vendor/driver application flows, broader role authorization, stock concurrency, and end-to-end integration still need tests.
- Delivery fee selection still chooses the lowest `feeBase` for a city and ignores `feePerKm`. Do not rely on this calculation for commercial orders until delivery-zone semantics and pricing rules are defined.
- DeliveryZone currently has no spatial polygon/radius field, so the correct zone cannot be inferred spatially from the current schema.
- Firebase push notifications, maps/geocoding, and live driver tracking are not verified end to end.
- Online payment is not implemented as a usable provider flow; cash on delivery only.
- Refresh-token rotation and logout revocation were implemented on the active PR branch using Redis-backed token hashes and atomic compare-and-swap. Confirm the PR is merged and deployed before relying on this behavior.
- OTP verification now uses one atomic Redis operation on the active PR branch, with bounded attempts and replay prevention. Confirm the PR is merged and deployed before relying on this behavior.
- Secure first-admin bootstrap procedure and production role provisioning still require review.
- Latest previously released CI run #21 (`e788a045afbb00a43415d7e04cdbf69b79e0f3ad`) completed successfully: backend packages built, Flutter analyze/build passed, artifact uploaded, and release published. This remains a Debug build, not a signed production release. A production signing key and release build pipeline must be configured securely.
- The Render Free + Supabase Free + Upstash Free setup is preview infrastructure only. It is not approved for live customer data or commercial order traffic; backups, restore, availability, quotas, and capacity need an approved production plan.
